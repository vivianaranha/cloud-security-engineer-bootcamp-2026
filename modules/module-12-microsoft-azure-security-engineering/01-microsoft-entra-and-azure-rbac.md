# Tutorial 12.1 — Microsoft Entra and Azure RBAC

**Created by School of AI**

**Module:** Microsoft Azure Security Engineering

## Objective
Apply **microsoft entra and azure rbac** to a production cloud security architecture.

## Engineering method
1. Identify account/subscription/project and resource scope.
2. Identify human and workload identities.
3. Map trust boundaries and exposure.
4. Classify data.
5. Define preventive guardrails.
6. Define detective telemetry.
7. Define evidence and ownership.
8. Define containment and recovery.
9. Test the control.
10. Track residual risk.

## Design questions
- Can this resource be reached publicly?
- Who can administer it?
- Which workload identity does it use?
- Where are credentials and keys stored?
- Which audit event proves access/change?
- What prevents configuration drift?
- How is compromise contained?
- How is recovery tested?

## Azure lens
Map the control to Microsoft Entra ID, Azure RBAC, Azure networking/data protection, Azure Monitor and Defender for Cloud capabilities.

## Hands-on checkpoint
Produce a control design, evidence requirement, misconfiguration test, remediation and recovery action.

> Assess only cloud environments you own or are explicitly authorized to review.
